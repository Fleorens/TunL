## Contexte

À partir de cette fiche, **aucun texte d'interface n'est écrit en dur** (sauf `src/dev/`, le nom de marque « TunL »
et les symboles techniques comme `SSH`). L'anglais est la langue de référence, le français est complet.
Le choix de la langue sera un réglage en T08/T09. Pour l'instant, on suit la langue du système.

Vérifié sur ce poste : avec `initAsync: false` et des ressources embarquées, la traduction est disponible dès le premier
rendu. Le français utilise les pluriels `_one`, `_many` et `_other` : `Intl.PluralRules("fr")` renvoie `many` pour
1 000 000.

### 3. `src/i18n/locales/fr.json`

Mêmes clés, en français (casse de phrase, ton neutre, cf. `03-design.md` §7) :
`"tagline": "Gestionnaire de connexions SSH, SFTP et RDP"`, `cancel` → « Annuler », `save` → « Enregistrer »,
`close` → « Fermer », `delete` → « Supprimer », `edit` → « Modifier », `retry` → « Réessayer »,
`search` → « Rechercher », `details` → « Détails », `online` → « En ligne », `connecting` → « Connexion… »,
`offline` → « Hors ligne », `error` → « Erreur », `unknown` → « Inconnu », `system` → « Système »,
`dark` → « Sombre », `light` → « Clair », `language.system` → « Langue du système ». Les noms de langue restent
« English » et « Français » dans les deux fichiers.

### 4. `src/i18n/index.ts`

```ts
import i18next from "i18next";
import { initReactI18next } from "react-i18next";
import en from "./locales/en.json";
import fr from "./locales/fr.json";

export const SUPPORTED_LANGUAGES = ["en", "fr"] as const;
export type SupportedLanguage = (typeof SUPPORTED_LANGUAGES)[number];
export type LanguagePreference = "system" | SupportedLanguage;

export function detectSystemLanguage(languages: readonly string[]): SupportedLanguage {
  for (const tag of languages) {
    const base = tag.toLowerCase().split("-")[0];
    if (base === "fr" || base === "en") {
      return base;
    }
  }
  return "en";
}

export function resolveLanguage(
  preference: LanguagePreference,
  systemLanguages: readonly string[],
): SupportedLanguage {
  return preference === "system" ? detectSystemLanguage(systemLanguages) : preference;
}

export const i18n = i18next.createInstance();

void i18n.use(initReactI18next).init({
  resources: { en: { translation: en }, fr: { translation: fr } },
  lng: resolveLanguage("system", navigator.languages),
  fallbackLng: "en",
  interpolation: { escapeValue: false }, // React already escapes rendered text
  initAsync: false,
});

document.documentElement.lang = i18n.language;

export async function setLanguage(preference: LanguagePreference): Promise<void> {
  const language = resolveLanguage(preference, navigator.languages);
  await i18n.changeLanguage(language);
  document.documentElement.lang = language;
}
```

### 7. Utiliser l'i18n dans les composants

La galerie `src/dev/` garde ses textes en anglais en dur, **sauf** deux endroits qui servent de démonstration :
- son sélecteur de thème utilise `t("theme.system")`, `t("theme.dark")` et `t("theme.light")` ;
- dans `AtomsSection.tsx`, les labels des `StatusDot` passent par `t("status.<état>")`.

On obtient `t` avec `const { t } = useTranslation();` (import depuis `react-i18next`).

Ajouter dans l'en-tête de la galerie un second sélecteur (trois boutons) : `t("language.system")`, `English`,
`Français`, qui appelle `setLanguage(...)`. Il permet de vérifier la bascule à l'œil.

### 8. Tests

**`src/i18n/locales.test.ts`** : parité des clés.

```ts
import { describe, expect, it } from "vitest";
import en from "./locales/en.json";
import fr from "./locales/fr.json";

const PLURAL_SUFFIX = /_(zero|one|two|few|many|other)$/;

function flattenKeys(value: unknown, prefix = ""): string[] {
  if (typeof value !== "object" || value === null) {
    return [prefix];
  }
  return Object.entries(value).flatMap(([key, child]) =>
    flattenKeys(child, prefix ? `${prefix}.${key}` : key),
  );
}

function normalizedKeys(resource: unknown): string[] {
  return [...new Set(flattenKeys(resource).map((key) => key.replace(PLURAL_SUFFIX, "")))].sort();
}

function leafValues(value: unknown): unknown[] {
  if (typeof value !== "object" || value === null) {
    return [value];
  }
  return Object.values(value).flatMap(leafValues);
}

describe("locales", () => {
  it("en and fr define the same keys (plural variants aside)", () => {
    expect(normalizedKeys(fr)).toEqual(normalizedKeys(en));
  });

  it("has no empty or non-string translation", () => {
    for (const value of [...leafValues(en), ...leafValues(fr)]) {
      expect(typeof value).toBe("string");
      expect(String(value).trim()).not.toBe("");
    }
  });
});
```

**`src/i18n/index.test.ts`** : `detectSystemLanguage` →
- `["fr-FR", "en-US"]` → `"fr"` ;
- `["de-DE", "en-GB"]` → `"en"` ;
- `["de-DE"]` → `"en"` ;
- `[]` → `"en"`.

`resolveLanguage("fr", ["en-US"])` → `"fr"`, et `resolveLanguage("system", ["fr-BE"])` → `"fr"`.

### 9. Règles i18n pour la suite (à respecter dans toutes les fiches)

- Clés en `camelCase`, groupées par domaine : `sidebar.favorites`, `editor.fields.host`, `errors.kind.timeout`.
- Interpolation : `"Connected to {{name}}"` → `t("toast.connected", { name })`.
- Pluriels : `key_one` + `key_other` en anglais ; `key_one` + `key_many` + `key_other` en français.
  Appel : `t("sidebar.count", { count })`.
- Jamais de phrase fabriquée par concaténation (`t("a") + " " + name`) : une seule clé avec interpolation.
- Les textes du Rust (messages d'`AppError`) ne sont **pas** traduits : l'UI traduit le `kind` (T05).
